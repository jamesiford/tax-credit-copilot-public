# Findings: things that look wrong, recorded unchanged

The Python implementation is the oracle. None of these was fixed or smoothed; each is in the recordings exactly as observed. A port must
decide, per item, whether to reproduce it (parity) or fix it deliberately (a recorded deviation). `case` names the recorded exchange
(`<recording>:<step id>`).

## Defects (5xx, hangs)

| # | Finding | Evidence |
|---|---|---|
| F-1 | `GET /api/simulate/portfolio/{year}?magnitude=999999999` never returns: it is CPU-bound with no bound or timeout. The case is **omitted from the scenarios** (it would hang the recorder); the other out-of-range magnitudes (`abc`, `-1`, `0`) are recorded. | found while recording `p1_reads`; excluded in `scenarios/build.py` |
| F-2 | `GET /api/v2/portfolio?scope=all` answers a plain-text **500**. | `p1_query_edges:portfolio.scope` |
| F-3 | `GET /api/v2/clients/99999999999999999999/units` (an id beyond 64 bits) answers a plain-text **500** (integer overflow in the store binding); a smaller unknown id answers a normal not-found. | `p1_query_edges:unknown.client-huge` |
| F-4 | `GET /api/progress/{year}?within=-1` answers a plain-text **500**. | `p1_reads:get-api-progress-tax-year.query-within-negative` |
| F-5 | A second `POST /api/clients/{id}/packages` for the same client and year answers **500**: the blob path is derived from the run and the content hash and "blob paths are never reused". The second build of an identical package is an unhandled error, not an idempotent 200 or a 409. | `p1_artifacts_ai:package.create-again` |
| F-6 | `GET /api/workspace/assumptions` answers a plain-text **500** while every other sealed-workspace route answers **503** with a JSON reason when the reference inputs are absent. | `p1_reads:ok.api-workspace-assumptions` |

Every 500 body is `text/plain; charset=utf-8` with the exact bytes `Internal Server Error`; it is not the `{"detail": ...}` JSON the
handled errors use. A client that always parses JSON fails on these.

## Environment findings

| # | Finding |
|---|---|
| E-1 | **Resolved.** The first recordings were made on CPython 3.14.2 while the product runs on 3.12. Measured on 3.12.13 (`uv python install 3.12`, backend requirements): the HTTP behaviour is the same, 1,755 / 1,769 exchanges identical, and the other 14 are only container size/hash fields (E-6). The earlier claim that 3.14 removed the default `sqlite3` date adapters was **wrong**: both 3.12.13 and 3.14.2 still ship the deprecated defaults for `date`/`datetime`, and both refuse a **subclass** ("type ... is not supported") because adapters are looked up by exact type; the harness freezes the clock with subclasses, so it registers its own adapters on every interpreter (`harness/freeze.py`), and asserts at start-up that on 3.12 they write exactly what the default adapters write. **Decision: 3.12 is the oracle**, enforced in code (`contract/oracle.py`): `CONTRACT_PYTHON` defaults to the 3.12 environment, and the tools refuse any other minor version unless `--allow-other-python` (cross-check only, stamped in the output). The recordings were re-made on 3.12.13; the 3.14.2 cross-check against them passes 1,769 / 1,769 strict and 12/12 `capture --check`. |
| E-2 | `backend/tests/data_engine_fixture.py` translates `SELECT TOP n` but not `SELECT DISTINCT TOP n`, which the unit drill issues; the fixture world therefore 500s on `GET /api/v2/clients/{id}/units/{unit}` until `harness/gold.py` adds the translation. Not a product defect. |
| E-3 | `RUN_WORKER_INLINE` defaults on for `ENVIRONMENT=local`; an API in that mode races a background worker against requests. The harness pins it off and exposes `POST /__contract__/drain`. |
| E-4 | A base-year save starts a daemon **recalculation thread** the response does not wait for; what the next read says depends on how fast it ran. The harness defers it until the response is sent and finishes it before the next request (`freeze._freeze_threads`, `control._gated`). A port must offer the same ordering for the replay to be repeatable. |
| E-5 | `RunClientCalculationCommand` writes claims as a side effect; `tests/data_engine_fixture.run_engine` therefore needs the operational claims repository passed in (the harness does) or the engine run's claim is lost. |
| E-6 | **Resolved by a declared normalisation.** The size and SHA-256 of a zip/xlsx container are not stable across interpreters: the 3.14.2 Windows build links **zlib-ng 2.2.4**, 3.12.13 links **zlib 1.3.2**, and the same 40 KB input at the same level deflates to different bytes (SHA-256 `5b882ebf...` vs `a75ff0ec...`; confirmed, not just suspected). Members were identical in all 14 differing exchanges (e.g. `POST /api/clients/1001/packages` `size_bytes` 10011 on 3.14 vs 10046 on 3.12, `sha256` differs; `package.year-uncalculated` 8495 vs 8477), so the difference is the deflate stream only. A .NET host will always write different bytes again. Those fields are now **tier D** (CONTRACT-REPORT section 6) and are replaced by `{container.size_bytes}` / `{container.sha256}` at record and replay time, at 7 listed routes only, after a shape check; the members are compared one by one and the container bytes never (`docs/normalisation.md`, `selftest.py`: 26 mutations of the server answer). The xlsx is also not byte-reproducible on one interpreter unless member timestamps are frozen (`freeze._freeze_zip`), as before. |
| E-7 | The governed data tools (`data_catalog`, `data_query`, `data_distinct_values`) answered 500 through the gateway in the first recording pass because the harness had not wired a data-query service; with the SQLite adapter wired (`harness/world.py`) they answer normally. A real deployment with the Warehouse unreachable was not exercised. |
| E-8 | Over a real socket, **uvicorn closes the connection after an unhandled exception** (it has already sent the plain-text 500). An HTTP client that reuses connections can write the next request on the socket just as the server closes it and gets `Server disconnected without sending a response` / `ReadError`; seen intermittently on the steps that follow a 500 (`p1_query_edges:portfolio.outcome`, `p1_workspace_unavailable:scope`) and reproducibly in the mutation self-test, which replays one server repeatedly. The replay client therefore opens a connection per request (`httpx.Limits(max_keepalive_connections=0)`). A port that does the same for its 500s will hit the same race in a keep-alive client. (The cause is inferred from the server log and confirmed by the fix, not by a packet capture.) |
| E-9 | The seed `.gz` files are gzip, so their bytes also depend on the zlib build: 13 of 31 differ between 3.12 and 3.14 while the decompressed content of all 31 is identical. `seed/*/manifest.json` now carries `content_sha256` (decompressed JSON Lines) next to `sha256` (the file as committed); a loader should verify `content_sha256`. Re-exporting on another interpreter changes only `sha256`. |
| E-10 | The inventory spelled a type with `str()`, which differs by interpreter (`Union` vs `A \| B` for a union response model) and leaked the harness: a `datetime` annotation printed as `contract.harness.freeze.FrozenDatetime`. It is now built from the typing structure (`inventory/typenames.py`: `Optional[X]` is `X \| None`, `Literal[...]`, builtins bare); `inventory.generate --check` passes on 3.12 and 3.14 from the one committed file. Every annotation in `routes.json` changed to the canonical spelling in the process (`<class 'int'>` is `int`, `typing.Literal[...]` is `Literal[...]`, and `dict` is now `dict[str, Any]` / `dict[str, object]`, which is what they always were); `untyped` flags did not change. |
